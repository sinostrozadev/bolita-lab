Bolita Lab Uploader — User flow diagrams

There is exactly one user: the channel owner. There is no sign-up, no public UI and no other users' data.

Flow A — One-time authorization (OAuth 2.0, desktop app)

1. Owner runsnpx tsx scripts/subir.mts autorizarLocal terminal
2. Tool prints the Google OAuth URLScopes: youtube.upload, youtube. Owner opens it in the browser.
3. Google account chooserOwner picks the channel's brand account "Bolita Lab".
4. Consent screenGoogle shows the requested permissions; owner clicks Continue.
5. Redirect to 127.0.0.1:8765Tool exchanges the code for tokens and stores them in secrets/youtube-token.json (owner-only).

Flow B — Daily upload of a rendered Short (automated, on the owner's computer)

1. Pipeline renders a ShortMP4 + title, description, tags, publish date written to a local JSON.
2. Upload tool reads the JSONsubir.mts subir --id … --publicar-en …
3. videos.insertResumable upload; privacyStatus=private + publishAt (scheduled).
4. thumbnails.setCustom thumbnail for the video.
5. Local state updatedVideo ID and dates saved in the JSON; owner sees it in YouTube Studio as "Scheduled".

Flow C — Weekly planning (read-only, own channel)

1. Weekly review scriptRuns on Monday on the owner's computer.
2. channels.list (mine=true) + videos.listPublic statistics of the owner's own videos only.
3. Local reportUsed to choose next week's topics. Nothing is shared or published.
Revocation. The owner can revoke access at myaccount.google.com/permissions at any time; the tool then stops working until re-authorized.
