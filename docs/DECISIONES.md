# Decisiones

- 2026-11-02 · Remotion 4.0.540 (React 19) como motor de render: código → video, determinista, ya probado en esta máquina.
- 2026-11-02 · Voz con `msedge-tts` (gratis, calidad neural). Riesgo: servicio no oficial; plan B = Azure Speech con las mismas voces, o Kokoro local en la RTX 3060.
- 2026-11-02 · Física precalculada en Node y guardada como JSON (no dentro del render) para que el audio y el video salgan del mismo evento.
- 2026-11-02 · Subida por YouTube Data API con OAuth propio. Los proyectos de API sin auditoría dejan los videos bloqueados en privado: hay que pedir la auditoría de cumplimiento (gratis) apenas exista el canal.
- 2026-11-04 · **Revisión semanal automática** (`scripts/revisar.mts`, cron lunes 05:00) por la orden de mejora continua (`docs/MEJORA-CONTINUA.md` §5): Santiago no debe tener que pedir la evaluación. Mira los videos (6 fotogramas por video + hoja de contacto, ffmpeg de Remotion; la hoja se compone en Node porque ese build no trae `tile`), baja métricas por API (Data API + YouTube Analytics; si falla, sigue y deja la instrucción) y le pide la revisión a `claude -p --model opus` con permisos cerrados (`--permission-mode dontAsk`, edición solo en `src/`, `scripts/`, `contenido/backlog/`, `contenido/calendario.json`, `package.json`, `docs/DECISIONES.md` y `docs/ESTRATEGIA.md`). Por el §2b también busca en la web Shorts virales del nicho y los vuelve reglas, propone/adopta herramientas gratuitas (los paquetes npm los instala el script, no Claude, para no podar el `node_modules` compartido) y evalúa la estrategia. Las mejoras se aplican en un **git worktree** con rama `revision/<fecha>` (no en el árbol principal, porque ahí suele haber trabajo de otras sesiones sin commitear y un `git clean` lo borraría) y solo llegan a la rama principal (fast-forward, sin push) si pasan `tsc` y el render de prueba de cada plantilla tocada; si no, se revierten y queda anotado en `salida/revisiones/<fecha>.md`.
- 2026-11-04 · **Producción en GitHub Actions** (`.github/workflows/producir.yml` y `compilar.yml`) para que la fábrica no dependa del PC de Santiago (WSL encendido, ~100 MB de RAM libre). Patrón: todo el código corre en Actions; secretos en GitHub Secrets (`YOUTUBE_CLIENT_JSON`, `YOUTUBE_TOKEN_JSON`, los carga Santiago); el estado vive en archivos commiteados por `bolita-bot` (json de bandeja, backlog/guiones movidos, hojas de contacto ≤150 KB, PARA-SUBIR-A-MANO.md) y los mp4 van a artifacts de 14 días (no al repo: 10–25 MB cada uno). "Cuando pase X" = `on: push` con `paths` sobre el backlog/calendario; el push del bot usa `GITHUB_TOKEN` y no dispara workflows. Sin `claude -p` en la nube: los guiones llegan hechos. Subida apagada (`BOLITA_SUBIR=0`) mientras el proyecto de API no esté auditado. **El cron local sigue hasta la auditoría**; al encender la subida en la nube hay que apagar el diario local para no duplicar. La compilación semanal también corre en la nube bajando los mp4 de los artifacts (si un artifact expiró, ese Short simplemente no entra).
